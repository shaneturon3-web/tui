# Provenance Entropy Engine

## Core Relation

A successful long-lived recurrence may exhibit:

`functional signal ↑`
while
`provenance signal ↓`

## Provenance Degradation Chain

Possible operations:

`origin`
→ `copy`
→ `local repair`
→ `rename`
→ `carrier rotation`
→ `partial forgetting`
→ `exaptation`
→ `independent reinvention`
→ `cross-contact`
→ `retrospective grouping`

Do not require every step.

## For Each Recurrence Track

- earliest located evidence;
- earliest claimed evidence;
- gaps;
- copied forms;
- independent analogues;
- local explanations;
- transmission opportunities;
- impossible transmission windows;
- later reinterpretations;
- observer-induced diffusion.

## Evidence States

Use explicitly:

- `EXISTS`
- `NOT LOCATED`
- `LACK OF EVIDENCE`

Never turn absence of provenance into proof of secrecy.

## Entropy Rule

As provenance degrades, do not compensate by making the invariant more obvious.

Sometimes both provenance and function become noisy.

## Useful Output

Create contradictory local pedigrees:

- two groups each claim the other borrowed it;
- an object predates the word;
- the word predates the current function;
- the same function appears where transmission seems impossible;
- a documented copy later becomes more different than an undocumented analogue.

## Failure Mode

If every recurrence points cleanly back to one source, this is genealogy exposition, not provenance entropy.
